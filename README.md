# LINK — сайт для скачивания

Статический сайт с описанием LINK, загрузкой версии для Windows и ссылкой на веб-версию. В репозитории находится только сайт: исходный код приложения, сервер, база данных, учётные записи и ключи сюда не входят. Установочные файлы хранятся на внешнем сервере релизов.

Сайт: [LINK](https://zov148.github.io/link-website/). Репозиторий: [zov148/link-website](https://github.com/zov148/link-website).

Сайт работает без сборки, установки Node.js, пакетов и платных сервисов. HTML, CSS, JavaScript, изображения и шрифт системы загружаются напрямую. Пути к ресурсам относительные, поэтому сайт подходит для GitHub Pages в подкаталоге репозитория.

## Проверка на компьютере

Откройте терминал в каталоге сайта и запустите любой локальный HTTP-сервер, например:

```sh
python -m http.server 8080
```

Затем откройте `http://localhost:8080/`. Простой запуск HTML через `file://` не подходит для проверки модулей и сетевой загрузки.

## Настройка ссылок

Публичные адреса приложения, API релизов и ссылки GitHub задаются в `assets/config.js`. Этот файл доступен всем посетителям: в нём допустимы только публичные URL. Секреты, токены и пароли в сайт не добавляются. Ссылки GitHub показываются только после указания настоящего адреса репозитория.

Потоковый загрузчик обращается к внешнему серверу релизов и перед сохранением проверяет размер и SHA-256 полученного файла. Обычные ссылки скачивают файл напрямую; для них контрольные суммы приведены на странице. При переносе сервера обновите публичные адреса и разрешённый источник запросов на сервере. GitHub Pages размещает сайт; сообщения, звонки и файлы приложения обслуживает отдельный сервер.

## Публикация на GitHub Pages

1. Разместите содержимое этого каталога в отдельном репозитории с основной веткой `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Откройте **Actions → Publish LINK website → Run workflow** либо отправьте изменение в `main`.
4. Адрес опубликованного сайта появится в результате задания `deploy` и в Settings → Pages.

Workflow копирует только перечисленные статические файлы. Публикация из других веток и pull request не запускается. Официальные GitHub Actions закреплены полными SHA коммитов; установка зависимостей и сборка сайта отсутствуют. Приватные ключи и дополнительные секреты для Pages не нужны.

Официальная инструкция: [настройка источника публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Сторонний компонент и права

Для потоковой проверки SHA-256 используется браузерная сборка `@noble/hashes` в `assets/vendor/hash/sha256.js`. Её исходная лицензия MIT и уведомление об авторских правах сохранены в [assets/vendor/hash/LICENSE.txt](assets/vendor/hash/LICENSE.txt). Эта лицензия относится к указанной библиотеке. Публикация сайта не предоставляет лицензию на исходный код приложения LINK или его фирменные материалы.
